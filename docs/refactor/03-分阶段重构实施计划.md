# Agent Runtime V2 重构实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不替换 LangChain 和不推翻 ReAct 能力的前提下，将 Runtime 改造成可恢复、可审计、上下文可控且 UI/数据库统一的数据驱动系统。

**Architecture:** 先固定持久化 schema 与纯领域契约，再修正 ReAct Core 的事件/outcome 语义；随后将编排拆成 TaskRuntime、PlannerWorkflow、ContextPipeline、CoreEventRecorder，最后替换 view/SSE/UI 投影。每一阶段都必须可独立运行和回归测试。

**Tech Stack:** TypeScript、NestJS、Fastify SSE、PostgreSQL、pg、LangChain、Vitest、React + TypeScript。

## 验收清单

- [ ] 用户发送消息后立即得到 committed user message patch。
- [ ] assistant 流式 delta 能按 `messageId + outputId` 合并，结束后数据库只存完整 content。
- [ ] 调用工具前 assistant tool call 已可在数据库和 UI 中看到。
- [ ] 工具失败不丢失同轮其他工具结果。
- [ ] 任意数量 HITL 并行等待，所有答案提交后只恢复一次。
- [ ] 刷新浏览器后 GET view 能恢复 pending input、plan progress、已完成 tool pairs 和 token usage。
- [ ] planner step 只有持久化 `step_result` 后才完成。
- [ ] final report 不包含 raw failed searches 或其他 step 的 ReAct system prompt。
- [ ] 同 session 双窗口不能并行启动两个 active root task。
- [ ] context usage 页面展示 provider 真实用量；provider 未返回时明确标记 estimated/unavailable。
